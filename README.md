# Sharktic

mygo로 만든 Windows 트레이 하드웨어 모니터입니다. 이름은 Shark + Arctic입니다.

- 트레이 아이콘 4개: PC 온도, CPU, GPU, RAM 수치
  - PC 온도는 70°C부터 주황, 85°C부터 빨강 / 사용량은 90%부터 빨강
  - 100은 두 자리 아이콘에 맞춰 99로 표시
  - 새 아이콘은 Windows가 트레이 화살표 안에 넣으므로, 밖으로 끌어내야 항상 보임
- 마우스 올리기: 전체 요약
- 왼쪽 클릭: 자세히 보기 패널 (CPU, 메모리 점유 상위 프로그램 포함)
- 오른쪽 클릭: 메뉴 (로그인 시 자동 실행, 진단 정보 복사, 종료)
- 진단 정보 복사: 모델명, BIOS·Windows 버전과 팬 관련 ASUS 펌웨어 항목 9개를 읽은 값을 클립보드에 복사. 펌웨어에는 읽기만 하며 설정은 바꾸지 않음. 다른 모델의 지원 여부를 확인하는 데 씀
- 예전 이름(Hardware Info)의 팬 설정과 로그인 시 자동 실행은 처음 시작할 때 새 이름으로 옮겨짐
- 측정할 수 없는 값은 `--`로 표시 (0%와 구분)
- ASUS 노트북: 패널에 팬 속도와 조용함, 균형, 터보 선택과 고급 설정 표시. 성능 모드와 팬 곡선은 펌웨어가 지원하는지 각각 확인해 있는 것만 보이고, 둘 다 없으면 숨김
  - 성능 모드 없이 팬 곡선만 있는 모델(ROG Strix G513 등으로 추정, 실기기 미확인)에서는 성능 모드 버튼 대신 앱이 만든 곡선 프리셋(조용함, 균형, 최대)을 보여 줌. 세 프리셋 모두 권장 하한을 지키고, 두 팬에 같은 곡선을 씀. 곡선은 바로 적용. 앱에서 펌웨어 곡선으로 되돌릴 방법이 없어 앱을 종료해도 곡선이 유지되며, 패널에 그렇게 표시됨
  - 성능 모드: 실제 팬 속도는 온도에 따라 펌웨어가 조절
  - 고급 설정: CPU, GPU 팬별로 8개 구간의 온도와 팬 속도를 표로 입력하고 그래프로 확인. 권장 하한(70°C 55%, 75°C 70%, 80°C 85%, 85°C 100%)보다 낮으면 경고하지만 적용은 됨. 값은 `%AppData%\Sharktic\fan-curves.json`에 저장됨. 앱을 종료하면 균형 모드로 돌아감
  - 마지막으로 고른 팬 설정은 `%AppData%\Sharktic\fan-choice.json`에 저장되어, 앱을 시작할 때 다시 적용됨. 아무것도 고른 적이 없거나 이전 버전의 수동 설정이 저장되어 있으면 펌웨어 설정을 건드리지 않음. 패널의 "컴퓨터를 켤 때 이 팬 설정 적용"을 켜면 로그인 시 앱이 자동 실행됨
  - 펌웨어가 현재 모드를 알려 주지 않으므로, 이 앱에서 고르기 전에는 선택 표시가 없고 Fn 키 등으로 바꾸면 표시와 달라질 수 있음

## 측정값 출처 (관리자 권한 불필요)

| 항목 | 출처 |
| --- | --- |
| CPU 사용량 | 성능 카운터 `% Processor Utility` (작업 관리자와 같은 계열의 값) |
| 메모리 | `GlobalMemoryStatusEx` |
| PC 온도 | 성능 카운터 `Thermal Zone Information` (ACPI). 부품별 센서가 아니며, 없는 PC에서는 `--` |
| GPU 사용량, 온도, 전용 메모리 | NVML (NVIDIA 드라이버에 포함). 끊기면 30초마다 다시 연결 |
| NVML이 없을 때의 GPU | 성능 카운터 `GPU Engine`, `GPU Adapter Memory`. 사용량과 사용 중인 메모리만, GPU가 여럿이면 가장 바쁜 값 |
| 팬 속도, 성능 모드, 팬 곡선 | ASUS System Control Interface 드라이버 (`\\.\ATKACPI`, 비공개 인터페이스, 관리자 권한 불필요) |
| 프로그램별 CPU, 메모리 | `NtQuerySystemInformation` (같은 이름의 프로세스는 합산, 서비스 호스트는 개별 표시, `vmmem` 등 작업 관리자 프로세스 탭에 없는 항목 제외). CPU는 실행 시간 비율을 전체 사용량에 맞춰 환산한 추정값 |

## 팬 제어 구조

제조사별 방식은 `fanBackend`(`fans.go`) 뒤에 있고, `detectFans`가 이 PC에 맞는 것을 고릅니다. 화면과 저장은 이 틀만 씁니다. 지금은 ASUS(`fan_asus_windows.go`)만 있습니다.

## 빌드

Go 1.27.3 이상이 필요합니다.

    go test ./...         # 이 PC의 실제 센서까지 검사
    go test -short ./...  # 계산과 화면만 검사 (PC에 따라 달라지지 않음)
    go tool mygo build -skip-installer

결과물: `build/windows-amd64/Sharktic.exe`

mygo는 입력칸 버그 수정(#1159)이 들어간 커밋 `6ec64b0`을 사용합니다. 이 수정이 포함된 정식 버전이 나오면 그 버전으로 올립니다.

## 다른 기기 조사 도구

`cmd/fan-probe`는 다른 노트북에서 Sharktic이 쓸 수 있는지, 지원하려면 무엇이 필요한지 정보를 모으는 콘솔 프로그램입니다. 읽기만 하고(ASUS는 DSTS 읽기만, WMI는 클래스 정의만 읽고 메서드는 부르지 않음) 관리자 권한도 필요 없습니다.

```
go build -o build/fan-probe.exe ./cmd/fan-probe
```

실행하면 프로그램 옆에 폴더와 zip을 만듭니다: `report.txt`(기기 정보, 판정, ASUS 항목, 제조사 WMI 클래스, 서비스, ACPI 장치), `acpi/`(레지스트리 `HKLM\HARDWARE\ACPI`에서 읽은 DSDT와 모든 SSDT, 오프라인 분석용), `wmi-vendor.txt`(제조사 클래스의 속성과 메서드 인자), `wmi-all.txt`(`root\wmi` 클래스 전체 이름).
